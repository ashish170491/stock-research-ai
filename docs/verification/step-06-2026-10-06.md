## Learning check
1. **What triggers a revision, and what happens if the critic still isn't satisfied after it?** `ResearchCritic.review()` returns a `Critique` with `verdict = REVISE` whenever it finds the draft unsupported, missing a data gap/conflict it should have surfaced, or missing an implied risk (`ResearchCritic.CRITIC_PROMPT`). `ResearchReportWriter.write()` then calls `writeInterpretation()` exactly once more with a revision prompt built from the critique's three lists and the previous draft (`revisionPrompt()`), bounded by `MAX_REVISIONS = 1`. If the critic reviews the revision and still says REVISE, the writer does not try again - it appends a visible footnote ("the revision limit (1) was already reached...") rather than silently either looping forever or hiding the critic's remaining concerns. The live HDFC Bank run hit exactly this path: the critic flagged issues on the first draft, the revision addressed some of them, and the critic still had concerns on the second pass - which the reader sees stated plainly.
2. **Why is the critic given `.entity(Critique.class)` instead of `.content()`, and why does that make it exempt from `EVIDENCE_RULES` the way `INTERPRETATION_PROMPT` isn't?** `.entity(...)` forces the model's reply into a fixed Java shape (four named fields, one enum) that Java then validates structurally - there's no free-text sentence from this call that could ever reach the reader directly; an unparseable reply becomes `Critique.accept()`, not displayed text. This is the same mechanism `ScreenerAgent`'s `ExtractedCriteria` extraction uses, and the invariants script already treats that extraction prompt as exempt from `EVIDENCE_RULES` for the same reason: the risk `EVIDENCE_RULES` guards against (a free-text claim about the company reaching the user unchecked) doesn't exist for a prompt whose only output is validated, structured judgement data.
3. **Why does `BearCaseWriter` run the same `NumericClaimVerifier` + `UnsupportedClaimFilter` chain as the main interpretation, rather than trusting the bear-case prompt's own "quote figures exactly, calculate nothing" instruction?** Because a prompt instruction is never itself a guarantee in this codebase's design (`CLAUDE.md`: "the LLM never calculates... judges"): the bear-case model call is just another `qwen3:8b` call that can hallucinate a figure despite being told not to (demonstrated directly in `BearCaseWriterTest.writesFromTheRestrictedEvidenceAndStripsAFigureNotInIt`, where a scripted "999.99%" is stripped). Running the same deterministic verifier chain on its output is what actually enforces the rule, independent of whether the model complied.
