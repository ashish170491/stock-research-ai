The tool's own summary says "3 of the 46 screened stocks meet every criterion". This is the same kind of problem as the 2026-09-28 misquoted bank threshold. - **My live checks triggered a log rollover that overwrote the Sep 28 log archive.** The app and the test JVMs both write `logs/stock-research-ai.log` with a daily rolling policy (`application.yml:178-195`). Before my curl calls, `logs/stock-research-ai.2026-09-28.0.log` was 528,314 bytes. After the app's first write of the day (my curl at 12:23:30), it was 46,142 bytes with mtime 12:21:02. That matches the test-run file of that size and time being renamed over the archive. The app's stdout copy still has lines from its 14:16 restart onwards. Fix: give tests their own log file, for example `logging.file.name` in a test `application.yml`, or disable the file appender in tests.
- **End-to-end chat latency.** The chat took 236 s, almost all in the second model round (a 15,552-char tool result). The screen itself took milliseconds. A more compact default result would help Step 4.
- **NBFC D/E is not blocked in code.** `IndustryGroup.NBFC`'s non-primary set (`IndustryGroup.java:32-34`) does not include `debtToEquityMultiple`, so only the config and `ScreeningPresetsTest` keep D/E out of NBFC presets. The spec asks only about banks.
- **Screening allowance lasts for the whole session.** `AiService.java:226` filters against `usage.evidence() + session.earlierEvidence()`. After one screen, later answers in the same conversation keep the "meets the supplied criterion" allowance.
- **Snapshot job edge case.** In `SnapshotJob.capture`, an exception thrown by `repository.recordFailure` itself (line 123) escapes the per-symbol catch and ends the run as FAILED.
- **CSV parsing.** `Universes` splits on `,` without handling quotes. The current file parses, but a company name containing a comma would stop startup.
- **Admin endpoints have no auth** (documented at `ScreeningController.java:29`). That's fine locally, but they need protecting before any shared deployment.
- **Deviations from the roadmap, allowed by the spec.** Only NIFTY50 exists, with no Next 50, Midcap 150 or watchlist. Spans are 3 years, not 5 (the reason is given at `application.yml:93-94`). `reasonable-value` uses an earnings-yield threshold. Insurers and FINANCIAL_OTHER are "Not screened" (4 stocks live).

## Learning check
1. **Where is "TCS passes ROCE ≥ 15%" decided, and what stops the model from deciding it?**
   `StockScreener.evaluate` (`StockScreener.java:56-73`) decides it in Java with `Operator.holds` on BigDecimals, from the stored snapshot. The model gets only the rendered table from the `screenStocks` tool. The tool description forbids recalculating, re-ranking or applying its own thresholds. EVIDENCE_RULES rule 5 limits it to "meets / does not meet the supplied criterion". `UnsupportedClaimFilter` allows that phrase only when `TOOL RESULT: screenStocks` is in the evidence, and it still removes labels such as "quality company" and "top pick".
2. **A bank's snapshot has D/E = 0.8x and operating margin 30%. Why do they never appear in its screen, and what happens if someone adds a BANK D/E rule to `application.yml`?**
   `ScreeningCriteria.rulesOf` gives BANK only its own `BANK:` rule set, and the `default` set never applies to FINANCIAL groups (lines 89-97). A BANK rule on `DEBT_TO_EQUITY_MULTIPLE` fails construction, because `IndustryGroup.BANK.isNonPrimary("debtToEquityMultiple")` is true (lines 60-67). The app therefore refuses to start, and `ScreeningPresetsTest.refusesAPresetThatTestsANonPrimaryMetricForItsGroup` pins this down.
3. **Why does a chat screen make no Yahoo calls, and how are the Yahoo calls in the nightly job kept safe?**
   The chat path is `ScreeningTools` → `ScreeningService` → `FundamentalsSnapshotRepository.latestCompletedRun/snapshots` (H2) → `StockScreener`, and none of these has a provider dependency. Only `SnapshotJob` reaches Yahoo, through `SnapshotBuilder` → `StockResearchService`. It runs as `@Scheduled` at 18:30 Asia/Kolkata on weekdays, or on `POST /api/admin/snapshot`. It pauses 1 s between companies on top of `YahooRequestThrottle`, allows one run at a time (`AtomicBoolean`), records per-symbol failures and carries on, and screening reads only the newest COMPLETED run. Live, run 4 took 58 s for 50 companies.
