## Learning check
1. **Why does `AiService` build the two `ChatClient`s with `.defaultAdvisors(conversationTraceAdvisor)` but no memory advisor, and pass `chatMemory.get(conversationId)` as `.messages(history)` by hand instead?** Because `MessageChatMemoryAdvisor` would add the model's raw response to memory as part of the advisor chain, before `AiService`'s own post-call code (`AnswerChecks` -> `NumericClaimVerifier`/`ScreeningCountVerifier`/`UnsupportedClaimFilter`) gets to remove unsupported claims from it. Doing memory by hand lets `remember()` be called only after `screened()` has produced the final, checked text (`AiService.java:286-289`), so nothing enters memory except what the user was actually shown - this is now what S1-2/S1-3/S1-8 describe directly, rather than naming the advisor class the design deliberately avoids.
2. **Why is a figure repeated from an earlier turn checked against `session.earlierEvidence()` rather than against the conversation's chat history text?** Because chat history (`chatMemory`) only ever contains text that already passed verification in its own turn - checking against it again would be redundant, and if it ever did contain something ungrounded, re-checking against it would let that figure "launder" itself into legitimacy just by having been said once. Checking against `ToolUsage.evidence()` (this turn) and `ResearchSession.earlierEvidence()` (up to 5 earlier turns, `EVIDENCE_TURNS = 5`) means a figure is accepted only because real tool output backs it.
3. **Why does a brand-new conversationId asking "and its debt?" get `NAME_THE_COMPANY` instead of an error or a guess, even while an unrelated conversation about Infosys is running at the same time?** `RequestRouter.needsACompany` is true exactly when the intent is `SPECIFIC_QUESTION`, the message names no company, the wording refers back to one, and the session (looked up by that conversation's own id via `ResearchSessions.get`) has no earlier company either. Because `ResearchSession`s are keyed per conversationId in a Caffeine cache, one conversation's `rememberCompanies` call can never be read by another's `companies()` call - confirmed live this run even under concurrent traffic to two different ids at once.
