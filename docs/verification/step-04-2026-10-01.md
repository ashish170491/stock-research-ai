## Learning check
1. **A user writes "3-year profit growth above 15%" but the model returns `NET_PROFIT_CAGR_5Y_PERCENT`. Which span is screened, and why?** The 3-year metric. In stage 2, `CriteriaValidator.spanned` reads the span from the criterion's own words first, then from the request if it names exactly one span, and only then the series default. It never uses the span the model picked. It then swaps in `ScreeningMetric.of(series, 3)`. This is tested in `CriteriaValidatorTest.measuresACriterionOverTheSpanItsOwnWordsName`. This is the chain idea: the LLM proposes structure, and Java decides with the user's words as the authority.
2. **Why does stage 1 bind to the all-string `ExtractedCriteria` rather than `ScreeningCriteria`?** If the model writes `PROMOTER_HOLDING` or `"18%"`, binding to an enum or `BigDecimal` would throw inside `.entity(...)`, and the user would never learn why. With strings, every value reaches `CriteriaValidator`. It checks the whitelist (`CriteriaValidator.java:328-333`), the bounds (`:340-345`) and that the threshold is a number the user actually wrote. Each problem becomes a visible "Not applied" note.
3. **How do the two separate ChatClient calls end up in one trace, and what checks the stage-4 output?** `ChainTracer.start` opens a trace context on the thread. Both clients carry the same `ConversationTraceAdvisor` (`ScreenerAgent.java:141`, `:146`), which logs "model call N" inside the open chain and does not start a new trace. `close()` logs `DONE ... | 2 model call(s)`. The summary draft goes through `AnswerChecks.check(draft, result)` (`ScreenerAgent.java:212`) against the full rendered result. NumericClaimVerifier catches figures, ScreeningCountVerifier catches the small counts NumericClaimVerifier skips, and UnsupportedClaimFilter removes judgements like "quality company". Each removal adds a note.
