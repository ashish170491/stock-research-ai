## Observations (outside scope, not affecting verdict)
- The live answer's INTERPRETATION section says "The earnings yield of 7.75% suggests a balance between growth potential and income generation" and "reflects the company's current valuation". This is an ungrounded judgement, and `UnsupportedClaimFilter` did not remove it. It is not a recommendation (so INV-5 holds), but it goes against the tool's "facts about the price, not judgements" framing. A pattern for "suggests a balance between growth ... and income" or similar interpretive phrasing could be added in research/report/UnsupportedClaimFilter.java.
- When a P/E conflicts, the reason text includes the application's cross-check figure, for example "differs from share price / trailing EPS (26.74, ...)". This number is derived by FinancialCalculator but is not recorded as a verifiable CALCULATED data point, and the model sees it in evidence. The model could quote 26.74 as "the P/E". Consider masking it, or recording it as a CALCULATED point.

## Learning check
1. **Why does `getValuation` return a markdown table through `PlainTextResultConverter` instead of the `ValuationResult` record as JSON, and how does the answer get checked against it?**
   The tool returns `renderer.renderValuationTool(result)`, and the same text is recorded on `ToolUsage` as `evidence` (StockResearchTools.java:144-145, 193-196). Compact text keeps the tool-loop context small (2208 chars for INFY). `ToolUsage` gives `NumericClaimVerifier` the exact text the model saw, so every figure in the answer, such as 12.90x, can be matched against it: `AiService.screened(draft, usage.evidence() + ...)` runs `NumericClaimVerifier.verify` and then `UnsupportedClaimFilter.filter` on that evidence (service/AiService.java:224, 249-251).
2. **When P/E is DATA_CONFLICT, what happens to earnings yield and why doesn't the model get to see a usable P/E?**
   `ValuationService.earningsYield` only calculates from a VALID P/E. Otherwise it returns `notCalculated(...)` with the P/E's status, which is DATA_CONFLICT with no value (ValuationService.java:127-134). The conflicted field `summaryDetail.trailingPE` is also added to the renderer's `Mask`, so the table shows `WITHHELD` instead of 40.00x (ResearchReportServiceTest `carriesValuationConflictsAndGapsIntoTheReport`). Java refuses to pick a side, so the LLM can't pick one either.
3. **For HDFC Bank, OCF/PAT might be VALID. Where is it stopped from becoming an observation, and where does the model learn why?**
   `IndustryGroup.BANK` lists `ocfToPat3yMultiple`, `ocfToPat5yMultiple` and `returnOnCapitalEmployedPercent` as non-primary. `ResearchReportService` turns candidate observations on those topics into `WithheldObservation` with reason SECTOR_CONTEXT. `UnsupportedClaimFilter` also has "cash conversion" and "return on capital employed" topic patterns, so a model sentence drawing a conclusion from them for a bank is removed (UnsupportedClaimFilter.java diff +154-158). The sector basis text explains that deposits and borrowings make capital-employed and cash-flow measures misleading for banks.
