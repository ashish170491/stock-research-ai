## Learning check
1. **Why is "What is ROCE?" answered with no model call at all, and what catches a phrasing the keywords miss?** `RequestRouter.byKeywords` checks `glossary.asked(message)` first (`RequestRouter.java:163-167`). If a glossary entry matches and `NseSymbolDirectory.namedIn` finds no company, it returns `EXPLAIN_TERM` without calling the routing `ChatClient`. If the keywords miss ("I keep seeing ROCE everywhere ..."), the routing model can still choose `EXPLAIN_TERM` from the routing prompt (`:55-56`). Even then `AiService` answers with `MetricGlossary.answer`, falling back to `termsIn(message)`, so the definition never comes from a model.
2. **Why is "Explain the terms" appended after `NumericClaimVerifier`/`UnsupportedClaimFilter` and kept out of the prompt and `ChatMemory`?** The checks judge model sentences against company evidence. Glossary text is not evidence about the company, and the model could paraphrase it into claims. So `ResearchReportWriter.write` builds the section from the already-rendered report (`:90-91`), and `AiService` remembers only a one-line note (`:170-171,191`). The next turn's prompt never contains glossary text the model could restate as its own.
3. **Where does "The quality-compounder screen uses ROE 3y avg ≥ 15.00%" come from, and why is it not written in `GlossaryEntries`?** `MetricGlossary.screenSettings` reads the `ScreeningPresets` bean (bound from `app.screening.presets`) on every render, using `Rule.label()`. A threshold copied into the text would become a second, unchecked copy of the screen's settings and would read as a standard. Reading it at runtime keeps `StockScreener`'s configured criteria as the only judgement. The test that changes the threshold to 18 shows this.
