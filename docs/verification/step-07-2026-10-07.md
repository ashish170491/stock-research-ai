## Learning check
Three questions the developer should be able to answer about this step's Spring AI concepts, answered from THIS codebase:

1. **Why does `searchCompanyDocuments` call `VectorStore.similaritySearch` directly inside an `@Tool` method instead of using `QuestionAnswerAdvisor`?**
   Because `QuestionAnswerAdvisor`/`RetrievalAugmentationAdvisor` splice retrieved text into the prompt *before* the model ever answers, outside the `ToolUsage` call log. `NumericClaimVerifier` and `UnsupportedClaimFilter` only ever see `usage.evidence()` - the concatenated text of recorded tool calls (`ToolUsage.evidence()`, `AiService.java:304`). An advisor's injected context would never appear there, so every figure in the retrieved annual-report text would be "ungrounded" and get stripped by the verifier unless the advisor's plumbing were duplicated into `ToolUsage`. Making retrieval an explicit `@Tool` that calls `ToolUsage.record`/`recordCitation` itself (`DocumentSearchTools.java:70-71`) means the same evidence-based verification pipeline that already covers Yahoo-sourced tools covers document search for free. This mirrors Step 1's reasoning for a manual `ChatMemory` over `MessageChatMemoryAdvisor` (see `docs/specs/step-01-memory.md` S1-2).

2. **Why is metadata tagged on the per-page `Document` before `TokenTextSplitter.apply`, not after?**
   `TokenTextSplitter` (like Spring AI's other `TextSplitter` implementations) copies the *source* document's metadata onto every chunk it produces, but it does not know anything about `symbol`/`docType`/`fiscalYear`/`page` - those are domain concepts the splitter has never heard of. If the raw, untagged pages were split first, the resulting chunks would carry no symbol/page metadata at all, and `searchCompanyDocuments`' `filterExpression("symbol == 'X'")` would have nothing to filter on, and no citation could be rendered. Tagging first (`DocumentIngestionService.java:53-61`) means every chunk the splitter produces inherits the correct symbol/doc type/fiscal year/page automatically.

3. **How does a citation make it into the user's answer even if the model's final sentence never mentions a page number?**
   Two independent paths. (1) The tool's own rendered text shows an inline `[SYMBOL — DOCTYPE FYyyyy, p. n]` tag before each chunk (`DocumentSearchTools.render`/`citation`, lines 74-100) which the model can see and optionally echo in prose. (2) Independently of that, every citation the tool actually returned is recorded on `ToolUsage.citations()` (`ToolUsage.recordCitation`, `DocumentSearchTools.java:70`), and `AiService.documentSourcesSection` (lines 247-258) appends a Java-rendered `"**Document sources**"` footer built straight from that list, appended *after* the screened answer (`AiService.java:219`) - so even a model that writes plain prose with zero citation markup still produces a final answer with the footer. `AiServiceRoutingTest.aDocumentSearchAnswerShowsItsCitationAndIsNotAttributedToYahoo` is the direct test: its `ScriptedModel` deliberately returns bare prose (`"The Gross NPA ratio was 1.24%."`, no bracketed citation) and the test still asserts the footer is present.
